## 概要 { #overview }

「理究」（RIKEN AI for Science 開発用スーパーコンピュータ）では、サービスレベルについて以下の目標を定め運用しています。

サービスレベルを保証するものではありませんが、改善を行うことで目標を維持できるように取り組んでいます。本文章は、商用クラウドサービスや他の HPC センター等のサービスレベル目標などを参考にして策定しました。

## 可用性 { #availability }

### サービス提供時間 { #service-hours }

「理究」は以下の事由によりサービスが提供できない場合を除く全ての時間において、サービスを提供します。このサービス期間中に利用した利用者からは、別途定める利用量に応じた利用料金をお支払いいただきます。

<div class="rules-items" markdown>

・ 別途定め広報する、計画的に実施する保守作業によるサービスの停止

・ 故障発生への対応など、不定期に発生する保守作業によるサービスの停止

・ サービス利用者が利用規則または法令などに違反しサービスが利用できない場合

・ サービス利用者または第三者の行為または不作為に起因しサービスが利用できない場合

・ 計算科学研究センター（以下、「センター」という。）が用意した本サービス用設備以外（サービス利用者環境、通信経路、他）の故障、障害などによる場合

・ センターが制御不可能な要因（自然災害、光熱費の高騰、暴動、テロ、戦争、政府機関の行為など）によりサービスが提供できない場合

・ その他，センターの責に帰すべき事由でない場合

</div>

また、稼働ノード数が常に最大となることを目指します。

### 計画停止 { #planned-outage }

保守などの計画停止を行う場合には、2 週間前を目処に通知を行います。

### 緊急保守 { #emergency-maintenance }

セキュリティ対策やシステムの稼働に大きな影響がある障害等が起きた場合には、緊急保守を行います。保守開始から 3 時間以内を目処に通知を行うことを目指します。

## サポート { #support }

### 提供時間・方法 { #support-hours }

平日の 9:00 から 17:00 に障害・保守・お問い合わせ等の対応を行います。サポートの受付はウェブフォームからとしますが、ウェブフォームが整備されるまでは電子メールでの問い合わせも受け付けます。

\*サポート提供時間は、年末年始・理化学研究所の定める休業日を除きます。

## 障害 { #failure }

### 障害検知・対応 { #failure-detection }

障害検知は 24 時間 365 日行いますが、利用者への障害通知やシステムの復旧作業は上記サポート提供時間内に行います。

### 通知 { #failure-notification }

システム全体に影響を及ぼす障害のうち、サポート提供時間内に発生・検知したものについては、発生を検知してから 3 時間以内を目処に通知することを目指します。サポート提供時間外の場合は、翌サポート提供時間の開始から 3 時間以内を目処に状況を通知することを目指します。

## データ { #data }

### データの保存 { #data-storage }

利用者のデータの保存用に、冗長性を持つストレージを装備しています。

利用者は、データの整理を行い、必要のないデータを放置しないよう務めてください。

### データのバックアップ { #data-backup }

システムでは利用者のデータのバックアップは一切行いません。

### データの消去 { #data-deletion }

課題実施期間終了日やアカウント削除日など、利用が終了したとみなされる日から 1 ヶ月後に課題などに割り当てたデータ領域を消去します。なお、ストレージ容量の逼迫などにより、センターからデータ削除を要請することがあります。

### データのアクセス制限 { #data-access }

利用者のデータは、他の利用者と共有するデータ領域に格納されており、UNIX のアクセス管理機能によってアクセス制限を実施しています。

## 計算資源 { #resources }

### 使用資源量 { #resource-usage }

使用した計算資源量は、利用したシステムの構成要素と実行時間の積である利用資源時間積で計算されます。ノードの故障などにより実行が中断した場合は、中断までの時間を実行時間として計算されます。使用資源量に伴う料金を利用者から徴収いたします。

### 資源返却 { #resource-refund }

使用した計算資源は原則として返却しません。ただし、以下に該当する場合は返却を検討します。

<div class="rules-items" markdown>

・ 正常な状況であれば有効な障害対応策（チェックポイント等）がシステムの問題で機能しない場合（原則ハード障害は返却対象外）

・ その他、利用者自身で解決または回避する方法がなく、資源返却が妥当とセンターが判断した場合

</div>

### 優先度 { #priority }

原則として課題毎の優先度に従い First-Come First-Served(FCFS)でスケジューリングされます。

## セキュリティ { #security }

### 取り組み { #security-measures }

「理究」や施設のセキュリティに対する取り組みについてご確認いただける「[セキュリティホワイトペーパー](security-whitepaper.md)」を公開しています。

### 脆弱性対応 { #vulnerabilities }

システムで使用しているソフトウェアで脆弱性が発見された場合は、センターが定めた対応基準に従ってセキュリティパッチの適用や対策を実施します。

### 暗号化 { #encryption }

「理究」への通信は SSH や HTTPS により暗号化されます。ストレージ上の利用者のデータは暗号化されません。
